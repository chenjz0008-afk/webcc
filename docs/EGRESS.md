# 账号容器出口白名单

2026-10-06 已部署生产。保护范围为 WebCC 管理的 ClewdR 账号容器，不覆盖服务器的 SSH、系统更新及其他应用，也不对请求内容自动脱敏。

每个账号使用独立 Docker bridge 网络。容器仅能向其代理的公网 IPv4 地址及 TCP 端口发起外部连接；其他 IPv4 出口默认拒绝，IPv6 禁用并有独立丢弃规则。直接 DNS 不开放，容器 DNS 指向不可用的本地解析入口。SOCKS5 配置自动转换为 SOCKS5h，通过代理解析上游域名。宿主机管理端口也禁止账号容器主动访问；管理网关已建立请求的返回流量允许通过。

## 生命周期

- `egress.py` 管理独立防火墙链，保留 Docker 原有规则；策略通过 iptables-restore 原子更新。
- `manager.worker_network` 先保存并安装出口策略，再创建网络和启动账号容器；规则失败则拒绝启动。
- 新增、修改代理、候选镜像、升级及回退均复用 `run_worker`，不修改官方 ClewdR。
- 恢复旧容器时核对网络模式，未迁移容器拒绝启动。
- `/var/lib/clewdr-manager/egress.json` 保存非凭据目的地址，权限 0600。它是账号配置的运行策略，不应手工编辑。
- `webcc-egress.service` 在 Docker 启动之前恢复规则。Docker 的 systemd drop-in 声明 Requires 和 After，恢复失败时 Docker 不启动。

规则同时挂载 DOCKER-USER、FORWARD 和 INPUT，针对 `wc` 前缀的专用 bridge 接口。当前服务器使用 iptables-nft 兼容后端；若更换为 Docker 原生 nftables 后端，需要重新适配并验收。部署方法依据 [Docker 官方防火墙文档](https://docs.docker.com/engine/network/firewall-iptables/)。

## 配置与维护

`MANAGER_PROXY_ONLY=true` 启用网络保护。当前实现要求代理使用固定公网 IPv4 和明确端口；域名代理、IPv6 代理及私网代理明确拒绝。支持 HTTP、HTTPS、SOCKS5 和 SOCKS5h，后两者在容器中统一为 SOCKS5h。变更代理请通过账号编辑功能，不能只手改 TOML，因为防火墙目的地址也需要同步。

安装时先停止已有管理服务并备份私有资料，安装模块和 systemd 单元，然后逐个迁移旧容器。安装脚本不自动迁移旧容器；已有部署必须完成迁移才能宣称受保护。不要将容器连接到其他网络或切换 host 模式，不要删除防火墙规则。拥有服务器 root 权限的人可以改变这些限制。

回退业务版本时必须保留出口保护模块、保护后的容器网络和启动挂钩。恢复最早的未受保护管理程序会使未来新容器缺少限制，不应直接回退。账号凭据和镜像仍可用原有备份恢复，但容器需要通过受保护的启动方法重建。

## 验收

| 范围 | 结果 |
| --- | --- |
| 服务器完整回归 | 111 项通过；最终 SOCKS5h 处理及网关定向回归 19 项通过 |
| 临时容器真实网络 | 指定代理连接成功；直接 HTTPS、DNS TCP、宿主管理端口及 IPv6 均失败 |
| 代理不在白名单 | 连接原代理失败，未回退直连 |
| DNS | Docker 解析入口返回 SERVFAIL，无解析答案；不开放直接 DNS |
| 临时模型请求 | SOCKS5h 下 HTTP 200，返回 Hi. |
| 生产 11 个账号 | 容器运行，全部采用独立网络；代理 TCP 成功，直接 HTTPS 全部失败，DNS/IPv6 配置符合限制 |
| 生产管理网关 | HTTP 200，返回 Hi.；管理服务、Nginx 和出口保护服务 active |
| 启动顺序 | 已核对 Docker 对出口恢复服务的 Requires/After；尚未进行整机重启实测 |

原始 SOCKS5 本地解析在封锁 DNS 后返回 500；临时验证确认改为 SOCKS5h 后恢复正常，生产迁移已统一处理。测试没有故意破坏生产代理或将账号隔离。

脱敏结果见 生产验收记录（历史记录已归档）。后续转发复核发现 ccb1 代理返回 SOCKS5 用户认证拒绝，Claude 调用返回连接错误；其余 10 个代理转发检查通过。代理 TCP 连接成功不代表认证或模型可用，需要在管理台更新 ccb1 的代理凭据。

这些证据证明当前容器网络的限制，不代表账号身份、代理服务商所见来源，或客户端主动上传的内容被匿名化。
