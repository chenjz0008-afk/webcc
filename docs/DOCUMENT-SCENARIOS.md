# 文档场景扩展验收

日期：2026-10-07。开发分支候选，未部署生产。测试使用服务器上的 cc1、ccb9 账号副本、官方容器、各自代理白名单网络、候选 HTTPS 和官方 TypeScript SDK 0.131.0。

## 结果

两个账号各五轮，共 10 次成功模型请求。模型按「四个读取→局部修改→回读→提交引用→总结」完成任务。读取由客户端测试执行器真实并发执行，结果按相反顺序回传，文档及工具 ID 正确对应。

| 场景 | 本轮证据 | 适用范围 |
| --- | --- | --- |
| 文档读取 | 区分标准与优先审阅两个相近段落；引用的段落 ID、行号和原文均与实际文件匹配 | 两份小型合成 Markdown，不是原生 citations API |
| 局部修改 | 仅 B-P2 的天数 30→14，并更新版本；A 字节不变，B-P1、表格、列表和链接源码保持 | 按唯一段落 ID 修改，执行器有目标和版本保护 |
| 多步任务 | 每轮工具实际执行；改后回读，再单独提交引用和总结；每个流程仅一次修改 | 本轮五轮流程，不代表任意长任务 |
| 并行任务 | 四个读取在线程池中执行，时间区间重叠；乱序回传不串文档 | 测试加入 30 ms 等待便于测量重叠，不是吞吐基准；未测试并发写入 |
| 格式保持 | 两个账号的文件检查通过；ccb9 增加 markdown-it 解析结构及期望 HTML 比对，每份文件的三个标题、一个表格、两层列表和链接属性保持 | Markdown 源码与 HTML 结构；未做截图或 DOCX 视觉排版验收 |
| 工具失败 | MISSING 返回 not_found，PRIVATE 返回 permission_denied；模型明确披露失败，未编造内容 | 测试执行器的文件可见性策略，不代替实际应用权限系统；版本冲突另见此前报告 |

提交引用与回读必须分轮，不能将尚未收到的回读结果当作证据。新增保护的四项定向回归通过；此前该轮完整回归 134 项通过。cc1 与 ccb9 的实际工具顺序也都满足分轮要求。

错误工具 ID、撤销密钥、不受信任证书在上游调用前被拒绝。SDK 可取得请求 ID，等待及并发槽位归零。两个测试的生产 registry 均保持不变，临时容器、配置副本、证书、依赖及合成文件已删除。

## 尚未验收

长文档、原生 thinking、慢工具与长流压力、修改中断后的幂等恢复、原生 Files 生命周期、真实 WordBuddy/Word/DOCX 集成及生产实验接口发布继续保留在待办中。网页工具策略仍需实验请求头和独立模型别名，业务工具由客户端执行，不宣称与原生 Claude API 完全等价。

测试没有使用 Mac Claude 配置、登录态或真实用户文件。模型只接收测试文档内容及逻辑 ID，不接收临时文件路径。测试代理和防火墙机制沿用现有出口保护。

## 重现

仅在部署服务器的隔离测试环境，以 root 运行：

```sh
python3 -m experiments.server_typescript --document-review --account=cc1
python3 -m experiments.server_typescript --document-review --account=ccb9
```

需服务器测试副本包含项目源码及 experiments 下的 SDK、渲染脚本。命令下载已校验的 Node 归档、安装固定测试依赖，复制账号配置，运行临时容器后清理。既有代理白名单网络必须存在；同名测试容器存在时直接停止，不覆盖生产容器。报告保存在服务器私有数据目录。
