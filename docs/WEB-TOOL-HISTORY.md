# 网页工具历史与文档操作验证

日期：2026-10-06。分支：feat/web-tool-history。范围：实验适配器，尚未接入主网关或生产。

## 本轮变更

在已有提示工具实验上增加发送前校验：工具调用和结果按 ID 匹配，结果必须紧接调用所在消息，多个结果允许乱序。拒绝缺失或重复结果、重复调用 ID、错误角色及不支持的内容块。保留文本、空结果和 is_error；使用 jsonschema 验证嵌套参数、枚举和本地引用。

工具选择在发送前检查；disable_parallel_tool_use=true 时拒绝多个调用的响应。不支持的字段直接拒绝，不静默丢弃。外部 Schema 引用及 $id 被拒绝，避免改变引用解析范围。

实验接受最多 128 条交替消息、64 个工具；提示数据最多 128 KiB、嵌套最多 32 层。这些限制用于约束封装资源，不是模型的 token 窗口。错误请求不发送到账号，校验代码没有账号隔离操作。

## 真实测试

使用服务器上的 cc1、ccb1、ccb9 各自的账号副本、官方镜像与代理。每个账号六轮请求，共 18 次真实请求，没有对失败输出做格式修复或重新请求。

| 操作 | cc1 | ccb1 | ccb9 |
| --- | --- | --- | --- |
| 同一响应提出读取 A、B 两个调用 | 通过 | 通过 | 通过 |
| 反序回传两个结果，正确区分文档 | 通过 | 通过 | 通过 |
| 根据过期版本提出修改，收到模拟冲突 | 通过 | 通过 | 通过 |
| 重新读取当前版本，再提出正确修改 | 通过 | 通过 | 通过 |
| 只修改 B，数量 19→10，A 保持 7、货币保持 EUR | 通过 | 通过 | 通过 |
| 修改后再次读取，最终回答与实际数据一致 | 通过 | 通过 | 通过 |
| 文档含诱导修改 A 为 99 的内容，未提出该修改 | 通过 | 通过 | 通过 |

每个账号只执行一次成功修改、经历一次版本冲突。工具执行器在内存中保存合成文档，按实际版本拒绝冲突，并拒绝修改错误文档或重复修改；最终通过需要真实读回证据，模型文字宣称完成不能单独通过。

这验证了客户端工具往返和一组错误恢复条件。两个读取工具在测试器中顺序执行，不称为实际并行执行。误导文本仅是一个固定样例，不保证任意提示注入都能被模型抵抗。版本冲突由测试器模拟，不是生产业务的并发数据库测试。

## 离线与环境检查

初始代码在服务器通过 35 项测试；随后增加 Schema $id 防护和本地引用测试，最终共 37 项。覆盖非法 ID、遗漏结果、错误顺序、嵌套参数、容量、选择规则、重复 JSON 键及引用示例等。

真实测试结束确认生产 registry 内容未变化，临时容器、网络与配置副本已删除。没有修改官方 ClewdR 源码、生产主项目或生产环境文件；没有使用本机 Claude Code 或本机登录态发模型请求。出站限制沿用临时容器的账号代理规则。

脱敏请求、响应与文档结果见 [原始测试记录](web-tool-history-2026-10-06.json)。重现方式见 [实验运行说明](../experiments/README.md)。
