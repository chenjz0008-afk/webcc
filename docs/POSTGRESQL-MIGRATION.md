# PostgreSQL 迁移与恢复

状态：2026-10-08 已部署。11 个账号、4 个调用密钥已迁移；文件使用 PostgreSQL BYTEA。公网文件生命周期、密钥撤销和真实模型请求已通过验证。

## 数据与服务

账号、调用密钥和更新配置按实体保存于 PostgreSQL JSONB 表。文件 ID、归属、到期时间和原始字节保存于 files 表。Redis 保存共享请求速率窗口，数据库保存账号占用与全局并发配置。

数据库和 Redis 当前只绑定服务器回环地址。多服务器连接必须另行配置私网、防火墙及 TLS；不能直接把这两个端口开放到公网。密码保存在服务器私有环境文件，禁止提交仓库。

## 切换顺序

1. 停止入口接收新请求，等待在途请求结束。
2. 停止管理服务，备份应用、环境文件、registry.json 和 files.sqlite3；备份目录权限 0700，文件权限 0600。
3. 执行 sudo bash deploy/install-cluster-runtime.sh 安装独立运行时，设置 MANAGER_DATABASE_URL 和 MANAGER_REDIS_URL。此脚本不创建数据库、不迁移数据，也不重启服务。
4. 对空目标库执行 deploy/migrate_state.py，核对账号、密钥和文件条数，以及文件元数据与原字节摘要。已有数据的目标库会被拒绝覆盖。
5. 再执行 --verify 独立核对。验证成功后启动候选服务，测试鉴权、撤销、文件上传/读取/删除、账号调度和真实模型调用。
6. 通过验收后恢复入口。保留原数据快照和数据库备份。

脚本从环境读取数据库连接，不在输出中打印密码或数据内容。MANAGER_DATABASE_URL 和 MANAGER_REDIS_URL 必须同时提供，数据库模式不会退回本地调度。

## 恢复

切换后尚未发生新写入时，可恢复原代码、环境和数据快照。已经有新写入时，不能直接恢复旧 JSON/SQLite；否则会丢失新密钥、撤销状态、账号变更和文件。

此时先停止入口与全部管理实例，核实在途任务与残留账号占用。使用 deploy/export_state.py 导出当前 PostgreSQL 状态到新的私有目录，再核对导出数据，恢复旧版本使用的数据目录。存在未解决占用时，导出脚本会拒绝操作。隔离数据库已验证文件原字节导出及占用阻断；生产恢复仍需停机后核对当前数据。

## 异常占用

进程退出后不会因为时间到期自动释放账号占用。先核实对应节点和容器是否仍有任务，暂停账号并停止容器，再由运维处理占用记录。禁止在不知道旧请求状态时清空占用表。恢复账号仍需管理员明确操作。

## 扩容边界

已经完成候选层面的同机多进程共享状态测试。独立节点 Agent、真实跨服务器路由、网关取消压测和语言对比还未验收；在这些门槛通过前，不应直接启动跨服务器网关副本承接流量。
